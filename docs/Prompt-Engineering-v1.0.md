## 📑 摘要
以**固定 Layer 1 保证评分口径一致**，以「4 个场景补丁 + 3 个水平补丁」完成差异化反馈，再由 Layer 3 独立生成总结、改写建议和异常兜底。核心目标是在保证跨场景数据可比的前提下，用 **8 个可组合模块覆盖 12 种模式（A1-D3）**，并为后续调试、版本管理和能力扩展保留清晰边界。

**系统边界（MVP 红线）：** 当前评分**仅基于转写文本中可观察的结构、措辞、重复、填充词和自我修正**，不推断音高、语速、停顿时长或情绪等音频特征；这些能力留作后续版本扩展（§7 设计亮点解释）。

## 🏗 §1 · 整体架构（三层不变量）
### 1.1 三层结构（职责拆分 · 责任边界清晰）
| 层级 | 中文名 | 定位 | 模块数 | 能做什么 | 绝不能做什么 |
|---|---|---|---|---|---|
| **Layer 1** | 基准评分层（固定） | 评分宪法 | 1（`LAYER1_BASE`） | 5 维定义 / L1-L4 锚定 / 5 分制映射 / JSON 输出格式约束 | 改评分；看场景/水平 |
| **Layer 2** | 分支补丁层（差异化） | 视角+语气补丁 | 7（4 场景+3 水平） | 调整 comment 与 suggestion 的**关注点、术语、严格程度** | 修改任何 score/level/label；引入未观察到的新事实 |
| **Layer 3** | 功能输出层（按需触发） | 功能独立模块 | 3（A 总结 + B 改写 + C 边界） | Module A 一句话 / Module B 句子级改写 / Module C 规则前置 | 破坏 Layer1 评分结果 |

### 1.2 完整执行流程（顺序红线，防循环偏差）
```
① Module C（规则）前置拦截
   ↓
② Layer 1 纯评分（scene=?，level=? 一律不看）→ 输出 5 维 score/level/label
   ↓
③ 本次 5 维均分 + 历史记录 → 计算 level_segment → 生成 mode_code
   ↓
④ Layer 2 注入 scene_patch + level_patch → 为 5 维生成 comment/suggestion
   ↓
⑤ Layer 3 Module A 输出 summary（≤20 字，先肯定后改进）
⑥ Layer 3 Module B 按阈值输出 improvements（A/B<3 / C/D<4）
```

> **设计不变量（红线）：**
> - Layer 1 绝对稳定
> - Layer 2 只能解释和表达，不能重算分数
> - Layer 3 各模块独立调用、独立降级；任一输出失败不应破坏已有评分结果

## 🧩 §2 · 模式编码系统（12 组合由 8 模块拼接，不维护 12 套 Prompt）
### 2.1 编码规则
`mode_code = {scene_code}{level_code}`，例如 **A1 = 话题聊天·新手**，**D3 = 面试·进阶**。

| 场景码 | 场景名 | 评估视角 |
|---|---|---|
| A | 话题聊天 | 有话题引导，围绕话题自由表达 |
| B | 自言自语 | 无指定话题，自由倾诉 |
| C | 演讲 | 有倒计时，参考演讲专业标准 |
| D | 单题面试 | 参考 STAR / PREP 结构化回答规范 |

| 水平码 | 水平名 | 判定标准（§2.1 + PRD §6.2） |
|---|---|---|
| 1 | 新手 | 有效练习 < 5 次（硬门槛，无论本次分数多高），或均分 < 2.5 |
| 2 | 成长中 | 2.5 ≤ 最近 5 条均分 ≤ 3.5 |
| 3 | 进阶 | 最近 5 条均分 > 3.5 |

### 2.2 工程化实现：运行时拼接公式
```js
mode_code = scene_code + level_code;  // A1 / D3 / ...
final_prompt =
  LAYER1_BASE +        // Layer 1（固定）
  SCENE_PATCH[scene] + // Layer 2 场景补丁（看什么）
  LEVEL_PATCH[level] + // Layer 2 水平补丁（怎么说）
  SCHEMA_CONSTRAINT;   // Layer 3 JSON 契约约束
```
**维护成本对比：** 8 模块 vs 12 套独立 Prompt → 一次标准调整只需改 1 处（`LAYER1_BASE`），不会出现版本漂移。

## 👮 §3 · Layer 1：基准评分层（评分宪法 · 完全固定）
### 3.1 定位
- 输入：ASR 转写文本
- 输出：仅 5 维 `{score, level, label}`，**不生成 comment 或 suggestion**（comment/suggestion 由 Layer2 生成）
- 评分规则：**先匹配等级锚点，再在该等级区间内微调小数**（不是先凭印象给分再倒推等级）

### 3.2 五维度完整锚定标准（Prompt 工程原文 · 5×4 = 20 条）
| 维度 | L1（1.0-1.9） | L2（2.0-2.9） | L3（3.0-3.9） | L4（4.0-5.0） |
|---|---|---|---|---|
| **1. 逻辑结构** | 自由发散：观点随意跳跃 | 初步成型：有起承转合但层次混杂 | 结构清晰：开头/主体/结尾明确 | 驾轻就熟：严谨、主次分明、推进自然 |
| **2. 语义清晰度** | 尚需揣摩：指代/因果模糊 | 基本可懂：大意可懂但有模糊词 | 表意准确：用词/指代基本准确 | 一语中的：精准具体、复杂信息无歧义 |
| **3. 流畅度** | 时有停顿：填充/重复/断裂频繁 | 基本流畅：可连续理解但仍有若干生硬 | 自然流畅：句间衔接自然 | 行云流水：表达连续节奏稳定，几乎无无效重复 |
| **4. 内容完整性** | 点到为止：只有结论或零散信息 | 有头有尾：表达闭合但论据薄弱 | 论据充分：有背景/理由/案例支撑 | 深入透彻：覆盖条件/证据/影响/结论闭环 |
| **5. 简洁度** | 略显冗余：同义重复或填充多 | 基本精炼：主要信息有效但仍可压缩 | 简洁有力：信息密度高，少量冗余 | 字字珠玑：高度凝练，每句推动理解 |

### 3.3 Prompt 正文
全文已内联复制到两处可执行代码（评审开代码可直接与本页逐字比对）：
- 前端兜底：[js/api.js PromptBuilder.LAYER1_BASE](../biaoda-lab/js/api.js)
- 后端代理：[api/analyze.js PROMPT_BUILDER.LAYER1_BASE](../biaoda-lab/api/analyze.js)

## 🎨 §4 · Layer 2：分支补丁层（4 场景 × 3 水平 = 7 个补丁）
### 4.1 定位与约束
> **补丁只改 comment 与 suggestion 的**「关注点 + 语气措辞」，**绝不修改 score/level/label**（§4.1 末句，后端 analyze.js 有 validateContract 强制校验，违者重试）。

### 4.2 四个场景补丁（决定"看什么"）
| 补丁 | 场景 | 重点关注维度 | 语气 |
|---|---|---|---|
| `SCENE_PATCH.A` | 话题聊天 | 逻辑结构（是否跑题）、内容完整性（是否完整回应话题） | 轻松自然，适合日常练习 |
| `SCENE_PATCH.B` | 自言自语 | 内容完整性（有清晰开始+结束为准）、逻辑结构（允许联想但线索可追踪） | 温和，鼓励持续开口 |
| `SCENE_PATCH.C` | 演讲 | 逻辑结构（开场/论述/收尾）、内容完整性（论据/案例）、语义清晰度（公开表达） | 专业明确，演讲专业标准 |
| `SCENE_PATCH.D` | 面试 | 逻辑结构（STAR/PREP 结构）、内容完整性（背景/行动/量化/结论） | 专业严格，面试答题标准 |

### 4.3 三个水平补丁（决定"怎么说"）
| 补丁 | 水平 | Comment 风格 | Suggestion 粒度 |
|---|---|---|---|
| `LEVEL_PATCH['1']` | 新手 | 温和、鼓励；聚焦最主要 1 个问题；不堆术语 | 足够具体，下次可直接尝试 |
| `LEVEL_PATCH['2']` | 成长中 | 客观指出问题；最多 2 个关联改进点；新术语用一句话解释 | 具体改进方向 |
| `LEVEL_PATCH['3']` | 进阶 | 直接精准；可使用 STAR/PREP/金字塔/Grice 等术语；好维度也说精进空间 | 讨论信息密度 / 论证质量 / 结构效率 / 措辞精度 |

### 4.4 冲突处理优先级
若补丁与 Layer 1 冲突 → **Layer 1 为准**；
若场景补丁与水平补丁冲突 → **场景补丁决定看什么，水平补丁决定怎么说**（职责分离）。

## 🧰 §5 · Layer 3：功能输出层（三个独立模块）

### 📌 Module A · AI 一句话总结（每次必触发）
**设计规格：**
- 字数：**≤ 20 个 Unicode 汉字**（用 `[...s].length` 计数，兼容 emoji/中日韩多 byte 字符）
- 结构：先肯定表现最好的 1 个维度 → 再指出最需改进的 1 个维度
- 语气：
  - 新手（1）：温暖鼓励，"啦/呀/更好～"
  - 成长中（2）：客观友好
  - 进阶（3）：简洁直接
- 人称：统一用"你"，不用"您"
- 禁止：复述分数 / 空泛评价

**作品级对照示例：**
- 场景二（流畅度 L4 最强 / 内容完整性 L2 偏弱）：
  - 新手：*"说得很流畅，内容再充实些就更好呀"*
  - 进阶：*"表达流畅，但内容支撑不足"*

**代码独立实现：** [js/api.js ModuleA(scores, levelSegment)](../biaoda-lab/js/api.js)

### ✏️ Module B ·「这样说会更好」（按场景动机差异化触发）
#### 触发阈值矩阵（§5.2 · 设计亮点 3）
| 场景 | 触发阈值 | 设计理由（用户动机对齐） |
|---|---|---|
| A 话题聊天 / B 自言自语 | **任一维度 score < 3.0** | 低压练习中 L3 已合格，频繁纠错削弱开口意愿 |
| C 演讲 / D 面试 | **任一维度 score < 4.0** | 专业场景目标更高，L3 也需要句子级示范以支持进阶训练 |

> 👉 **关键规则（防凑数）：** 高于阈值的维度**一律不生成改写**（不"为了有建议而给建议"）。

#### 输出格式
```jsonc
{
  "improvements": [
    {
      "original": "原句（必须是 transcript 逐字连续子串）",
      "improved": "改写句",
      "reason": ""   // level 1 = 空；level 2 = 简短说明；level 3 = 引用理论标签
    }
  ]
}
```

#### Level 3 专业理论标签池（作品展示用）
- PREP / 金字塔原理
- Grice 合作原则（方式准则 / 数量准则）
- Toulmin 论证模型
- Skehan & Foster (1999) 流利度研究
- 认知负荷理论

### 🚧 Module C · 边界处理（调用前由规则引擎执行）
#### 判定顺序 + 阈值（§5.3，顺序为硬红线）
| 异常类型 | 判定条件 | 前端引导文案 |
|---|---|---|
| 1️⃣ 空内容 | 转写为空或仅空白 | "好像没有录到声音，检查一下麦克风后再试试～" |
| 2️⃣ 字数过短 | 剥离空白/标点后有效汉字 **< 50** | "这次说得有点短，再多说几句效果会更好 🎙️" |
| 3️⃣ 乱码/识别失败 | 非汉字&非数字&非英文字符占比 > 50%，且无法形成连续可读文本 | "这次没有听清楚，要不要再试一次？" |

#### `insufficient_sample=true` 语义链
Module C 命中（too_short 为主）→ 所有维度后台写中性 2.0 / improvements=[] / 不进入成长统计（`Storage.getValidRecords()` 过滤）→ 前端 result 页黄色眉栏"⚠内容较短，不纳入统计" → profile 日志显示"样本较短"标签 → 完全符合 PRD §6.5。

## 📜 §6 · 最终输出 JSON 契约（校验规则）
成功响应必须满足以下规则（后端 analyze.js `validateContract()` 执行，失败自动重试一次，仍失败抛 5xx 走前端兜底）：

| 规则条目 | 约束 |
|---|---|
| `mode_code` | 正则 `^[A-D][1-3]$` |
| `dimensions` | **固定 5 项**，顺序固定：structure/clarity/fluency/completeness/conciseness |
| `score` | `[1.0, 5.0]`，一位小数 |
| `level ↔ score ↔ label` | **三者三重锁定一致**（label 不信任模型造词，由前端固定映射覆盖） |
| `comment / suggestion` | 每维度均非空；suggestion 为 15-20 字且可直接执行 |
| `summary` | ≤ 20 个 Unicode 汉字 |
| `improvements` | 0-3 项；每项 original/improved 非空；`original` 必须为 transcript 连续子串；level 1 时 reason 为空字符串 |

## 💡 §7 · 设计亮点（面试口述版，作品集 3 条金句）
1. **评分尺固定，成长曲线可比**：Layer 1 是"宪法"，面试和聊天模式下 3.5 分代表同一份能力，用户可横向比较进步；场景差异放到 comment/suggestion 处理。
2. **8 模块拼接，而不是 12 套独立 Prompt**：一次标准调整改 1 处，维护成本低；模块边界清晰，可单独测试 / 调参 / 回滚。
3. **改写阈值因"动机"而异**：低压聊天 A/B 仅 L1/L2 给改写（保护开口积极性）；高压演讲/面试 C/D 连 L3 也纠（用户主动寻求严格反馈）。分数相同，产品反馈强度随用户目标调整。
